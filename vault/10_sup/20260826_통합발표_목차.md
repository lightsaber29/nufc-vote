## 0. 전제 — 왜 프론트가 먼저인가

| 근거 | 내용 |
|---|---|
| 순서 일치 | 인프라 분석에서 뽑은 ① 렌더링·캐싱 → ② SQL 최적화 순서를 그대로 따른다 |
| 주장이 이어짐 | 프론트 = "**언제** 가져오느냐", 백엔드 = "**얼마나** 가져오느냐" |
| 인과로 묶임 | 프론트가 만든 정적 생성/캐싱 구조가 백엔드 결함(잘린 집계)을 **더 오래 굳힌다** (백엔드 원문 5.4) |
| 반전을 마지막에 | "SQL 최적화하러 갔더니 고칠 성능이 없었다 → 대신 틀린 값을 찾았다"가 전체 클라이맥스. 중간에 두면 소모된다 |

> 백엔드를 먼저 두는 안도 성립한다("병목이 없다 → 그럼 어디? → 출발선"). 다만 안티클라이맥스로 열게 되고,
> 청중이 초반에 "그래서 뭘 개선했다는 건가"를 오래 안고 간다. 5분 발표에서는 치명적이라 택하지 않는다.

### 분량 전제

한국어 발표는 분당 약 300자. **5분 = 말할 수 있는 분량 약 1,500자.**
원본 두 문서는 합쳐 28KB다. 대부분은 본문이 아니라 부록으로 내려야 한다.

## 2. 장별 구성 메모

### 1장 — 출발점

두 포인트를 **번호로 띄워두고** 발표 내내 이정표로 쓴다.
4장·5장에서 "②로 갑니다"만 말하면 청중이 위치를 잃지 않는다.

### 2장 — 출발선 (프론트 원문 1·2장)

Before/After 다이어그램 두 개를 **한 화면 좌우 배치**.

```
Before  HTML 수신 → JS 번들 → React 실행 → useEffect → 그제서야 요청
After   서버에서 Supabase 조회(병렬) → HTML 생성 → 이미 채워진 화면 도착
```

- `page.tsx` 코드는 **뺀다.** `Promise.all`로 병렬이라는 건 캡션 한 줄로.
- 5분 발표에서 코드를 읽히면 20초가 날아간다.

### 3장 — 캐싱은 짝이다 (프론트 원문 3·6장)

TTL 표 5행은 과하다. **세 항목만** 남긴다.

| 데이터 | TTL |
|---|---|
| 홈 투표 섹션 / 목록 | 30초 |
| 선수 후보 명단 | 3600초 |
| 내 예측 제출 내역 | **캐시 제외** (사용자별 데이터) |

같은 장에 Lighthouse 수치를 붙여 "정책 → 결과"를 한 화면에서 끝낸다.

- LCP **14.4s → 4.89s** (약 -66%)
- 서버 응답 **10ms** — "서버로 옮기면 TTFB가 늦어진다"에 대한 답

> 4차 77점 하락은 **여기서 말하지 않는다.** 7장 남은 과제로 미룬다.

### 4장 — 다리 (백엔드 원문 5.4)

텍스트 두 줄짜리 전환 슬라이드. **이 한 장이 두 발표를 인과로 묶는다.**

> `/polls`는 빌드 산출물에서 `○ (Static)`이다.
> 잘린 집계가 빌드 시점에 고정돼 그대로 서빙된다.

### 5장 — 규모를 만든다 (백엔드 원문 2장)

```
목표: DAU 100명 × 투표 10개 × 1인 1표 = 1,000표
```

여기에 **행 증폭 대비**만 덧붙인다.

| 유형 | 제출 1회당 행 수 |
|---|---|
| 선택형 | `votes` 1행 |
| 평점형 | `rating_votes` **14행** (선수 수만큼) |

시드 스크립트, `random()` 금지, staging 가드는 전부 부록.

### 6장 — 반전 ★ (백엔드 원문 4.4 / 5.1 / 7.2)

표 하나로 끝낸다.

| | 예상 | 실측 |
|---|---|---|
| 성능 | 병목을 찾을 것 | **77배 여유 — 고칠 게 없다** |
| 정확성 | 문제 없음 | **참여 500건이 화면에 72건** |

- 원인 한 줄: PostgREST `db-max-rows` 기본값 1,000
- 임계값 한 줄: 선수 14명 기준 **참여자 14명**에서 이미 틀린다
- 조건 A/B/C 세 표는 부록

### 7장 — 배운 것 + 남은 과제

배운 것 2줄로 압축:

1. 성능 문제는 "무엇이 느린가"보다 **"어디서 시작하는가"**를 먼저 본다
2. 최적화는 트레이드오프다. **캐싱은 그 짝이지 별개 작업이 아니다**

남은 과제 3줄:

- Hydration mismatch (React #423) — 3차·4차 동일 재현, 최우선
- Cache-Control 회귀 — 팀 로고 캐시 수명 7일 → 0
- `getRatingParticipantCounts` 서버 측 집계(RPC/뷰) 전환

## 4. 버리는 것

5분에는 자리가 없고, 빼도 두 파트의 인과가 끊기지 않는다.

- 이미지 최적화 (sharp 프리셋, next/image)
- `prefetch={false}` 선반입 차단
- 홈 캐러셀 SQL limit (`HOME_SECTION_ITEM_LIMIT`)
- 1차 10만 표 시드 실패담 (`ORDER BY random()` 상관 서브쿼리)
- 프론트 원문의 기존 Q&A 4개 → 필요하면 부록으로
