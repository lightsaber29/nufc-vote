"Supabase가 느리다"가 아니라, Supabase 데이터를 언제 가져오느냐가 초기 화면 성능에 영향을 줄 수 있다**는 이야기

기존
브라우저가 JS를 받아서 React가 실행된 다음에야 Supabase 요청이 시작

현재
Server Component에서 조회 -> 브라우저 페이지를 받았을 때부터 조회 가능
그러나 서버 응답 자체(TTFB)가 늦어질 수도 있어.
그래서 캐싱이 중요해짐. next.js 에 캐싱을 해 두고 쓰면 되니까
(현재 상태: next에서 선 조회, 30초 캐싱, 서버 컴포넌트, 병렬조회 promise.all)

현재 구조
사용자 요청
↓
Next.js 서버 (Vercel)
↓
Supabase 조회
↓
데이터 획득
↓
HTML/RSC 생성
↓
브라우저에 전달
↓
화면 표시
↓
HomeClient Hydration

TTFB(Time To First Byte) 가 늦어질 수 있음

그래서 내가 개선한 점
1. 서버 컴포넌트에서 선 조회 하도록 설정
2. 30초 캐싱처리
3. 서로 연괸되지 않는 기능들은 Promise.all 로 병렬조회
4. 화면에 노출되는 투표 수만큼만 SQL 로 투표 조회
5. next/image라는 게 이미 들어 있어요. 이걸 쓰면 표시할 크기에 맞춰 서버가 미리 줄여서 보내주고, 용량이 작은 최신 포맷(WebP/AVIF)으로 바꿔서 줍니다
